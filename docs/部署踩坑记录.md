# 部署踩坑记录（910B 真机实录）

> 本文记录在 CANNLab 2×910B（64GB×2）、CANN 9.0.0、Ubuntu 20.04 aarch64 环境中
> 从零跑通 MiniMax-H3 全流程中遇到的**每一个坑**及修复方法。

---

## 一、环境层

### 1. torchaudio 版本必须与 torch 严格一致

**症状**：ComfyUI 启动即崩：

```
OSError: .../torchaudio/lib/_torchaudio.abi3.so: undefined symbol: torch_library_impl
```

**原因**：pip 装 ComfyUI 依赖时把 torchaudio 升到了 2.11，与预装的 torch 2.7.1 不匹配。

**修复**：

```bash
pip install "torchaudio==2.7.1" --index-url https://download.pytorch.org/whl/cpu
# 或国内: pip install "torchaudio==2.7.1" -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 2. aarch64 的 libgomp TLS 报错

**症状**：

```
OSError: /lib/aarch64-linux-gnu/libgomp.so.1: cannot allocate memory in static TLS block
```

**原因**：aarch64 下通过 dlopen 加载 libgomp 时的经典问题。

**修复**：启动前预加载：

```bash
export LD_PRELOAD=/lib/aarch64-linux-gnu/libgomp.so.1
```

（`scripts/start_comfyui.sh` 已内置）

### 3. CANN 不在默认路径

CANNLab 模板的 CANN 可能在 `~/Ascend/ascend-toolkit` 而不是 `/usr/local/Ascend/ascend-toolkit`。
`setup.sh` / `start_comfyui.sh` 会自动探测两处并 source `set_env.sh`。

### 4. ComfyUI 依赖里的 py3.12 专属包

**症状**：`pip install -r requirements.txt` 报
`comfyui-workflow-templates-media-assets-02==0.1.11 ... requires python >=3.12`

**修复**：跳过这两个包，单独用 `--no-deps` 装（仅影响模板浏览器，不影响运行）：

```bash
grep -v -E 'comfyui-workflow-templates|comfyui-embedded-docs' requirements.txt > /tmp/req_core.txt
pip install -r /tmp/req_core.txt
pip install --no-deps comfyui-workflow-templates comfyui-embedded-docs
```

## 二、昇腾适配层

### 5. 必须锁定 ComfyUI commit

昇腾适配补丁基于固定版本，**不能**用 main 最新代码：

```bash
git fetch --depth 1 origin bd34f338ac505ea79e43968753968a464060e609
git checkout --detach FETCH_HEAD
git apply comfy-ui-changes.patch   # --check 通过再 apply
```

补丁来源：`https://atomgit.com/Ascend-SACT/MiniMax-H3-Comfy-NPU`

### 6. 权重格式：只用 int8_convrot

昇腾上：
- ✅ `*_int8_convrot.safetensors`
- ❌ `*_nvfp4*`（NVIDIA Blackwell 专属）
- ❌ `*_fp8_scaled`（建议避开）
- ⚠️ BF16 可行但显存吃紧，且官方推荐 INT8（速度 2 倍）

### 7. npu_count 必须等于实际卡数

工作流里 `MultiNPUParallelConfig` 节点默认可能是 4，双卡机器上必须改 2，否则运行前校验失败。
`scripts/set_npu_count.py` 会自动按检测到的卡数批量修改所有工作流。

### 8. 音频 VAE 必须 fp32

用 fp16 的音频 VAE → **没声音或音画不同步**，这个坑社区反复踩。

## 三、下载与存储

### 9. hf_hub_download 单连接只有 ~2MB/s

官方下载器在这类环境里单连接约 2MB/s，90GB 要下十几个小时。

**修复**：`scripts/dl_models.py` 用**分片并行**（16 连接/文件，Range 断点续传），实测聚合 **40MB/s**，
89GB 全程约 35 分钟。

### 10. gitcode 镜像不可用、hf-mirror 可用

实测 `ai.gitcode.com` 对这类环境几乎无速度（~100B/s），`hf-mirror.com` 正常。

### 11. 多套一层的目录陷阱

用 `hf_hub_download` 时若 `filename` 带子目录（如 `vae/xxx.safetensors`），且 `local_dir` 又指定到 `models/vae`，
会生成 `models/vae/vae/xxx.safetensors`。**下载后检查并拍平目录**。

## 四、出片流水线

### 12. 单次最长 15 秒

模型训练区间 124~362 帧（24fps，17k+5 对齐）。超了会崩或严重变形。
长片用 `scripts/driver_grid.py`：分段生成 → 抽尾帧 → 接下一段首帧 → 拼接。

### 13. ComfyUI 的 /prompt API 只认 API 格式

UI 工作流 JSON 不能直接提交。`scripts/convert_wf.py` 实现了转换，注意三个易错点：

- **COMBO / STRING / INT 等控件不能按"连线"处理**（否则 npu_count 等值会丢失）
- **动态输入**（如数学节点的 `values.a`）在 object_info 里没有，要从 UI 的 inputs 数组补充
- **LoadImage 只认 `ComfyUI/input/` 根目录**的文件名（子目录不扫）

### 14. 拼接用流拷贝，零重编码

```bash
ffmpeg -f concat -safe 0 -i list.txt -c copy out.mp4
```

服务器上若无 ffmpeg：`pip install imageio-ffmpeg`（自带静态二进制）。

### 15. sqlite 太老导致 history 落库报错（不致命）

```
sqlite3.OperationalError: near "ON": syntax error
```

系统 sqlite 版本过低不支持 UPSERT 语法，只影响历史记录面板，不影响生成。

## 五、远程访问（CANNLab 场景）

### 16. VS Code 转发通道的两个坑

- **Windows 自带 OpenSSH 与该转发桥不兼容**：连上即 `message authentication code incorrect`，
  改用 Git Bash 的 OpenSSH（10.x）即可（`windows/打开ComfyUI界面.bat` 是自愈版参考实现）
- **长连接会被周期性掐断（约 5 分钟）**：属转发桥特性，用「断线自动重连 + 15 秒退避」的循环脚本即可稳定使用
- 辅助进程彻底卡死时：taskkill 掉监听 <你的SSH端口> 端口的 Code.exe 子进程，VS Code 会自动重建

### 17. 大文件 scp 必须校验

隧道抖动会导致传输静默截断。**务必比对 size 或 md5** 再使用（本仓库文档中的脚本已内置重试逻辑）。
