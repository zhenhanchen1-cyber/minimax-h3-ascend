# MiniMax-H3 出片操作手册（华为昇腾 910B ×2 / CANNLab）

> 目标：从零开始，自己动手出第一条视频。全程 5 分钟上手。

---

## 第 0 步：确认服务在跑

服务跑在服务器上，你的浏览器看不到它，需要**先建一条 SSH 隧道**。

在你**本机**开一个终端（CMD / PowerShell / Git Bash 都行），执行：

```bash
ssh -L 8188:localhost:8188 -p <你的SSH端口> developer@127.0.0.1 -i <你的KEY路径>
```

⚠️ **这个窗口要一直开着**，关掉隧道就断了。

然后浏览器打开 **http://127.0.0.1:8188** —— 看到 ComfyUI 界面就成了。

如果打不开，说明服务没启动，让我或你在服务器终端执行：

```bash
bash /mnt/workspace/start_comfyui.sh
```

---

## 第 1 步：加载工作流

ComfyUI 界面里：

1. 顶部菜单 **Workflows → Open**（或左侧 Workflows 侧边栏）
2. 找到 `minimax-h3` 目录
3. 打开 **`fl2va_8steps_lora_int8_2npu.json`**

> 这就是我给你配好的那份：INT8 主模型 + heretic 文本编码器 + 2 卡。别选 `fl2va_8steps_lora.json`（那份是 BF16 + 4 卡，你这台跑不了）。

加载后画布上会出现一堆方块（节点），其中三块彩色 Note 是说明文字，可以先不看。

---

## 第 2 步：核对 6 个模型节点（关键）

节点上出现**红色报错**就说明选错了。逐个确认：

| 节点类型 | 应该选的值 |
|---|---|
| **UNETLoader** | `minimax_h3_fl2va_int8_convrot.safetensors` |
| **CLIPLoader** | `qwen3vl_32b_h3_ultra_uncensored_heretic_int8_convrot.safetensors`（type 保持 `minimax`） |
| **VAELoader**（视频） | `minimax_h3_video_vae_fp16.safetensors` |
| **VAELoader**（音频） | `minimax_h3_audio_vae_fp32.safetensors` ← **必须是 fp32** |
| **MiniMaxH3TurboLoRA** | `minimax_h3_turbo_v4_step600_ema.safetensors` |
| **MultiNPUParallelConfig** | `npu_count` = **2** ← 你这台是 2 个 NPU，填 1 或 4 都会报错 |

> ⚠️ 两个 VAELoader 长得一模一样，**别接反**。接反的表现是：有画面但没声音，或音画不同步。

---

## 第 3 步：写提示词

找到 **「Input Text (Prompt)」** 这个节点，在文本框里写。

**H3 听得懂镜头语言，别堆关键词。**

❌ 不好的写法（这是玩 SD 的旧习惯）：

```
一个女人，咖啡馆，下雨，电影感，8k，高质量
```

✅ 好的写法（交代清楚画面 + 动作 + 镜头 + 光 + 声音）：

```
黄昏的咖啡馆靠窗位置，窗外下着小雨。一位穿米色针织衫的女性正低头搅拌咖啡，
镜头从她的手部特写缓慢上摇至面部，她抬头看向窗外，嘴角微微上扬。
暖色调室内灯光，窗外冷色调环境光形成对比。
背景音：雨声、咖啡杯轻碰声、隐约的爵士乐。
```

**要点：**
- 中文直接写就行，模型支持
- 镜头术语它都认：推、拉、摇、移、跟、升降 / dolly in、pan left、crane shot、handheld
- **一定要写声音**——音频是跟画面一起生成的，你不写它就瞎猜
- 默认提示词是给"首帧→尾帧过渡"用的，**你要自己出片就把它整段替换掉**

---

## 第 4 步：调画质和时长

### 画质 → 「Resolution Selector (Size)」节点

- `aspect_ratio`：选 `16:9 (Widescreen)`（横屏）
- `megapixels`：控制分辨率，对照表（16:9，官方给的）

| megapixels | 输出分辨率 | 说明 |
|---|---|---|
| 0.2 | 608×352 | 极快，糊 |
| **0.4** | **864×480** | ⭐ 起步推荐 |
| 0.6 | 1056×608 | 清晰度不错 |
| **0.98** | **1344×768** | ⭐ 768P 标准档 |
| 1.2 | 1504×832 | 慢，但很清晰 |
| 2.0 | 1920×1088 | 接近 1080P，很慢 |

### 时长 → 「Float (Duration)」节点

直接填**秒数**。内部会自动换算成帧数（24fps，按 17k+5 对齐）。

- 最短 5 秒，官方训练区间 **5~15 秒**（124 帧 ≈ 5s，362 帧 ≈ 15s）
- 超过 15 秒属于未测试区域，容易崩

---

## 第 5 步：放不放图片（首帧 / 尾帧）

画布上有 **「First Frame」** 和 **「Last Frame」** 两个 LoadImage 节点：

- **纯文生视频（不用图）**：把这两个节点的连线**断开**。方法：鼠标按住连线拖到空白处，或右键节点 → Disconnect。首帧尾帧都是可选输入，断掉就是纯文字生成。
- **图生视频（一张图动起来）**：只保留 **First Frame**，断开 Last Frame
- **首尾帧过渡**：两个都接上（默认状态）

上传图片：点 LoadImage 节点上的 **「choose file to upload」**，选本地图片即可。
也可以把图片丢到服务器的 `/mnt/workspace/ComfyUI/input/` 目录，刷新后就能在下拉框里选到。

---

## 第 6 步：出片！

点右上角 **Run**（或按 `Ctrl + Enter`）。

然后等。进度条在界面上走，服务器终端也能看到。

**参考耗时（你这台 2×910B）：**

| 配置 | 耗时 |
|---|---|
| 480P / 5 秒（0.4 MP） | **约 90 秒** ⭐ 已实测 |
| 768P / 5 秒（0.98 MP） | 约 2~3 分钟 |
| 768P / 15 秒 | 约 7~8 分钟 |

> 第一次跑会慢一些（要把 34GB 主模型和 26GB 文本编码器搬进 NPU），**第二次开始明显变快**。

---

## 第 7 步：拿到视频

视频存在服务器的 `/mnt/workspace/ComfyUI/output/video/` 里。

**方式 A（推荐）**：界面上右键结果 → Save，直接下载到本机。

**方式 B**：在本机终端 scp 拉回来：

```bash
scp -P <你的SSH端口> developer@127.0.0.1:/mnt/workspace/ComfyUI/output/video/minimax_h3_fl2va_8steps_00001_.mp4 <本地目录>\
```

## 常见问题排查

| 症状 | 原因 / 解决 |
|---|---|
| 有画面没声音 | 音频 VAE 用了 fp16，必须是 **fp32** |
| 音画不同步 | 两个 VAE 接反了，回到节点检查连线 |
| 报 "device count" 错误 | `MultiNPUParallelConfig` 的 npu_count 改成 **2** |
| 报节点找不到 / 红色 | ComfyUI 版本不对，或没加载我给的 int8 工作流 |
| 卡住不动 / 疑似爆显存 | 降 megapixels、缩短时长；然后重启服务 `bash /mnt/workspace/start_comfyui.sh` |
| 人物变形、画面崩 | 分辨率拉太低了，试试 0.6 MP 以上 |
| 想让同一个人出现在多个镜头 | 换用 `ref2va_8steps_lora.json` 工作流 + 主模型换成 `minimax_h3_ref2va_pruned_int8_convrot.safetensors`，用 Ref2VA 喂 3~5 张同一个人的参考图锁角色 |

---

## 进阶：想做超过 15 秒的片子

单次最长 15 秒是硬限制。做法：**尾帧接首帧**——把第一段视频的最后一帧导出，作为第二段的首帧输入，配合 Ref2VA 锁住角色，就能串出连贯的长片。

## 三档速度工作流（按需求选）

| 工作流 | 步数 | 分辨率 | 时长 | 实测耗时 | 适合 |
|---|---|---|---|---|---|
| `fl2va_4step_极速档.json` | 4 | 0.4MP (864×480) | 5 秒 | 采样 17.8 秒；连续出片约 20~25 秒/条 | 快速试提示词、批量出片 |
| `fl2va_4step_0.6MP中间档.json` | 4 | 0.6MP (1024×576) | 8 秒 | 约 40~60 秒/条 | ⭐ 日常推荐，画质/速度平衡 |
| `fl2va_8steps_lora_int8_2npu.json` | 8 | 可自调到 1.0MP | 可自调 12 秒 | 1.0MP/12 秒约 11 分钟 | 要最高画质、做长片分段 |

> 提速杠杆排序：**分辨率 >> 帧数 > 步数**。0.4MP→1.0MP 每步耗时从 4.4 秒涨到 71 秒（16 倍）；步数 8→4 只快 2 倍。

## 隧道故障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 连接瞬间报 `message authentication code incorrect` | Windows 自带 ssh 与 VS Code 转发桥不兼容 | 用 `打开ComfyUI界面.bat`（已改为调用 Git Bash 的 OpenSSH） |
| 每 5 分钟左右掉一次 | VS Code 转发桥会周期性破坏长连接 | 正常现象，bat 会自动 15 秒后重连；浏览器断几秒自动恢复 |
| 完全连不上（反复同错） | VS Code 转发辅助进程卡死 | 关掉 VS Code 重开；或让我 taskkill 该进程 |
